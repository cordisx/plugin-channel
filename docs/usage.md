# Channel 使用指南

Channel 连接飞书等消息平台。登录和连接凭据由 CordisX 管理；插件页面提供连接、消息规则和任务绑定管理。

## 查看远端会话与本地对话的关系

支持 Channel Manager v10 的 Host 在“连接与会话”显示远端群聊／私聊卡片，使用真实群头像及平台图标；头像不可用时保留平台图标。点击卡片进入当前连接的子级详情，面包屑为“渠道 → 连接名 → 群聊／私聊名”。

“消息记录”查看本机 Channel 保留的实际接收和发送记录，包括排队、重试、失败及结果未知；只有获得平台回执的消息显示已发送。本地 Codex 对话的 commentary／final 不会自动出现在发送记录里。这里不是飞书完整历史，查询仅涵盖本地保留的记录，并支持分页。

“本地对话”显示该远端会话的全部本地绑定，包括已归档绑定，可打开实际 Codex 对话、修改执行设置、归档或解绑。打开仅导航，不启动模型任务。旧 Host 保留原有绑定列表。

群聊当前设为“仅 @”时，指令也需要 @ 机器人；查看绑定使用 `/bind-status`，查看接收与投递状态使用 `/messages-status`。`/help` 列出支持的指令；`/status` 不是当前指令。

## 让一个 Codex 对话监听多个会话

先用运行窗口对应的 Channel CLI 查询 connections 和 conversations，选择实际账号与私聊或群聊。使用 bind 把当前 Codex 对话绑定为 listen，之后通过 history 检索绑定后已接收且被接受的本地消息；deliver 把定向消息交给模型。若 Host 支持 remote-history，可指定账号、会话、时间范围和分页读取远端消息；群历史不保证展开所有话题回复。一个 Codex 对话可以监听多个群，一个群也可以绑定多个 Codex 对话，没有持久绑定数量上限。不要猜账号或会话 ID。

远端历史依赖同一机器人应用的消息读取权限；权限不足会返回明确错误，不自动切换账号。使用 CLI 的 help remote-history 查看参数和分页；[Host Channel 指南](https://github.com/cordisx/cordisx/blob/main/.agents/docs/channel-cli.md)说明授权步骤及官方 Lark CLI／Skill 联动。

## 回复和主动发送

默认关闭最终回复自动转发。Codex 的 commentary 和 final 留在本地工作对话，外部消息必须显式调用 CLI send 或 send-many。入站任务提供精确的 CLI、CordisX home 和 profile；按这个入口发送，不使用另一套 PATH CLI。conversation 发到主消息流，reply 引用原消息，thread 创建或回复话题；后两者需要 replyTo。每次发送使用稳定 operationId，结果未知时查询 receipt，避免盲目重发。用户明确需要自动转发时再打开开关；Agent 可以选择该 turn 的回复方式或 none。

入站任务的 messageContext 包含平台、群聊／私聊、发送者 ID、可解析的姓名和 @ 对象。目录查找失败仍交付消息，姓名只用于展示，不作为权限依据。CLI 的 --context 关联当前真实入站消息；请保留它。准确的当前实例查询和规则允许的来源会话回复默认单次放行；这不会放开任意 Shell 命令、其他账号或配置修改。

## 在频道里提问

需要澄清时，优先通过入站任务提供的精确 Channel CLI 向对应用户提问。原生询问工具的界面可能只在本地 Codex 窗口可见，频道用户无法在那里作答。Agent 可以选择 send 普通文字或 ask 可选问题列表；ask 在飞书／Lark 发送选项卡片，其他支持的适配器发送编号文本。旧 Host 没有 ask 时使用 send 发送编号选项。

ask 的输入包括 account、target、question、options（每项为 label 和 value）及稳定的 operationId。保留当前入站任务的 --profile 和 --context；target 使用已知的来源会话。用户看到简短的 label，本地任务收到对应 value 及问题内容。可设置 expiresInSeconds；飞书／Lark 的 targetUserId 只限制谁能点击回答，不隐藏卡片，也不限制普通文字消息。其他适配器不支持这个点击限制。

完成发送并核对回执后，等待同一频道的后续回答，不要把本地 final 当作提问，也不要为了等回答持续占用一个工具调用。飞书卡片既可点击选项，也可填写文字并提交；两者都以真实操作者的身份进入符合消息规则的绑定对话。在群聊直接发送普通文字时，仍需遵循原有的 @ 或唤醒词规则；卡片内提交不会唤醒无关闲聊。显示姓名和选项文本都不扩大用户权限。

用 receipt 查询同一 operationId 的投递结果；只有 sent 回执能确认已发送。question-cancel 撤销后不再接受按钮回答，但不会撤回已发出的卡片；过期或重复点击不会再次提交同一用户的回答。普通文字继续遵循既有消息规则。

先用当前 CLI 的 help ask 和 help question-cancel 查看实际支持的操作和参数。卡片能力由运行中的 Host 提供；安装插件手册不会让旧 Host 获得交互题能力。

## 私聊与群聊

私聊的定向消息可以自动创建 Codex 对话。群接收模式支持仅 @ 和接收全部；接收全部也不会自动回复闲聊，@、配置的唤醒前缀或明确命令决定是否交给模型。允许／拒绝规则支持全局及账号、会话、群／私聊、用户或用户组交集，拒绝优先。

新建任务默认放在“外部连接”分组，可在消息规则页修改。标题使用平台加私聊用户或群名；没有目录权限时先显示私聊／群聊占位，后续刷新。用户手动改名、移动后不自动覆盖。

## 执行设置与权限审批

统一设置中的「续接」默认关闭，启用后的默认比例为实际原生自动压缩阈值的 90%，最高 95%。例如原始窗口 100K、实际压缩阈值 80K、比例 50%，触发量是 40K。单个 Session 的明确覆盖优先于 profile 默认值；清除覆盖后继承默认值。新任务准备就绪后再接管旧任务；原生用量事件的时机不能保证阻止自动压缩。表单和保存由 Host 管理，旧 Host 未提供能力时显示不可用。

通用「新建对话默认配置」入口在「模型服务」页右上角，供普通对话使用。支持 Channel Manager v13 时，频道统一设置入口的「新建对话」页编辑独立覆盖层：先继承通用配置，再覆盖明确设置的字段；继承和未设置的字段继续使用通用值，明确的 false 保留。更细的频道任务模型规则保持优先级。旧 Host 的频道新建配置表单仍编辑通用默认值，不能把它当作独立覆盖层。

任务绑定列表可打开单个 Codex 对话的执行设置。执行范围、是否询问审批、执行／Plan 模式、思考强度、网络访问分别保存。修改下一 turn 应用；修改创建默认值不会改变已有或恢复的对话。never 不扩大执行范围。

需要批准原生命令或文件修改时，Channel 发送自定义交互卡片，摘要、状态和按钮始终可见，完整原因、命令与参数默认折叠。用户组允许的审批人可以点击批准这一次、本会话批准、拒绝，或发送 /approve 编号 once、/approve 编号 session、/deny 编号。按钮只是提交；卡片等待原生确认更新。/approvals 查询待处理项。审批通知不依赖自动转发开关。

支持 Channel Manager v12 时，统一设置入口的“模型配置”可设置服务商、模型和强度的新建默认值，以及群／用户范围规则。绑定任务也能打开模型设置。匹配的默认值在第一次模型执行前应用；已有任务在空闲时切换。有权限的用户可以直接使用 /model、/provider、/task-settings 或 AI 工具修改；无权限时生成固定的一次变更申请，有对应字段、服务商和模型权限的真实用户可用卡片或 /task-approve 批准。重启后的未知执行结果不会自动重复。旧 Host 隐藏模型配置页。

## 指令和文档

/help 查看可用指令；/help permissions 查看具体用法。多绑定且没指定目标时会列出可读候选；/choose 选择码 all 或 /choose 选择码 1,2 继续同一个操作。用户、账号和会话必须一致，选择后重新核对规则。

独立文档随包提供，也可在插件 README 页面打开。CLI docs 只读查询，help 操作名无需连接服务。
